| 항목 | 내용 |
|---|---|
| 문서 버전 | 0.3 (통합본 — 인스타·카카오를 한 구조로 서술, FR 번호 재정리) |
| 작성일 | 2026-09-07 |
| 상태 | 초안. 인스타 M0 완료 후 §9.1 외부 값 확정, 카카오 PoC 판정 후 FR-15~18 우선순위 확정 |

## 1. 배경과 문제

- **인스타그램 DM:** 데스크탑에서 쓰려면 instagram.com 탭을 열어 둬야 하고, 무거운 웹앱이라 메시지 도착 후 화면 반영이 늦거나 새로고침이 필요할 때가 있다. 다른 사이트에서 작업 중이면 탭을 전환해야 하고, 백그라운드 탭은 브라우저 스로틀링 때문에 더 늦다. 공식 API는 비즈니스 계정·앱 심사가 필요하고 개인 계정 DM을 지원하지 않는다.
- **카카오톡:** 공식 웹 클라이언트가 없어 브라우저 안에서는 아예 볼 수 없다. PC 앱을 따로 띄워 두고 창을 오가야 한다. 공식 메시지 API는 보내기 전용이라 받은 메시지를 읽을 수 없다.
- **공통:** 두 메신저를 각각 다른 창에서 확인하느라 작업 흐름이 끊긴다. 원하는 것은 "어떤 사이트에서든 한 버블로 둘 다 보고 텍스트로 답하는 것".

## 2. 목표 / 비목표

### 목표
- **G1.** 어떤 사이트에서든 클릭 한 번으로 인스타·카카오 대화 목록과 대화를 열고 텍스트로 답장한다. 사용자는 메신저 구분을 목록 표시로만 인지한다.
- **G2.** 인증 절차가 없다. instagram.com에 로그인돼 있고, PC 카카오톡에 로그인돼 있으면 그대로 동작한다.
- **G3.** 메시지가 화면에 뜨는 시간이 원래 클라이언트(백그라운드 인스타 웹 탭, 카톡 PC 알림)보다 짧거나 같다고 체감된다. 서버 전달 속도는 각 서비스가 정하므로 목표는 "도착 → 화면 표시" 구간이다.
- **G4.** 계정 제재 위험을 원래 클라이언트 사용 수준으로 유지한다. 인스타는 웹 세션·웹 엔드포인트만, 카카오는 PC 앱을 사용자 입력 1건당 1회만 조작한다.

### 비목표
- 사진/영상/음성/GIF/스티커/이모티콘 반응 전송, 게시물·스토리 공유, 파일 첨부
- 새 로그인 화면, 다중 계정, 계정 전환
- 인스타 실시간 프로토콜(MQTT/LightSpeed) 해석(v2 후보, ADR-003), 카카오 LOCO 프로토콜 구현(ADR-006)
- 제3자 "카톡 웹버전"류 스트리밍 서비스 사용
- Chrome 웹스토어 배포, Firefox/Safari, macOS 카카오 어댑터(v0.2 범위 밖)
- 자동 응답, 봇, 대량·예약 발송

## 3. 대상 사용자와 시나리오

- 사용자: 개발자 본인. 데스크탑 Chrome(Windows)에서 하루 종일 다른 사이트에서 작업하며 인스타 DM과 카톡을 자주 주고받는다.
- 시나리오 A: GitHub에서 코드를 보다가 버블 배지가 "2"로 바뀜 → 클릭 → 목록에 인스타 스레드와 카톡 방이 최근순으로 섞여 있음 → 카톡 방 열고 답장 → Esc로 닫고 복귀.
- 시나리오 B: 브라우저를 켬 → 확장이 핀 고정 인스타 탭을 열고 카카오 호스트에 연결 → 세션이 살아 있으면 아무것도 안 해도 목록이 뜸.
- 시나리오 C: 인스타 세션 만료 → 패널에 "인스타그램 로그인 필요" → [인스타그램 열기] → 로그인(2FA 포함) → 자동 복구. 카톡 쪽은 그동안 정상.
- 시나리오 D: 카톡 PC를 종료함 → 카카오 상태 `disconnected` 배너 → PC 카톡 다시 켜면 자동 복구.

## 5. 기능 요구사항

우선순위: **M**ust(해당 버전 필수) / **S**hould / **C**ould. FR-01~09 공통, FR-10~14 인스타 프로바이더, FR-15~18 카카오 프로바이더.

### 공통 (위젯·패널)

#### FR-01 플로팅 버블 (M, v0.1)
- http/https 모든 페이지의 최상위 프레임에 우하단 52px 원형 버블. `instagram.com`은 제외.
- 읽지 않은 스레드 수 배지(모든 프로바이더 합계). 0이면 숨김, 99 초과는 `99+`.
- 클릭으로 패널 토글. 패널이 열린 상태에서 호스트 페이지에 포커스가 있을 때 Esc로 닫힘.
- closed Shadow DOM + `adoptedStyleSheets`로 사이트 CSS와 격리. z-index 2147483647.
- 패널 iframe은 최초로 열 때만 로드한다(열지 않은 탭에서는 네트워크·포트 사용 없음).
- Trusted Types 강제 사이트(google.com 등)와 엄격한 CSP 사이트에서도 오류 없이 동작.
- **수용 기준:** google.com, github.com, youtube.com, naver.com에서 버블이 보이고 콘솔 오류가 없다.

#### FR-02 통합 스레드 목록 (M, v0.1 인스타만 / v0.2 통합)
- 모든 프로바이더의 스레드를 최근 활동순 하나의 목록으로. 행마다 프로바이더 표시(짧은 라벨 `IG`/`KT` 또는 색 점).
- 상단 필터 칩: 전체 / 인스타 / 카톡(켜진 프로바이더만). 기본 전체. 칩에 프로바이더별 안읽음 수.
- 행: 이름(인스타 `thread_title` 없으면 참여자 username 나열, 카톡은 방 이름), 마지막 메시지 미리보기(내가 보낸 건 `나: `, 그룹은 `발신자: ` 접두), 시간(오늘 `HH:mm`, 아니면 `M/D`), 안읽음 강조.
- 상단 바: 프로바이더별 상태 점(툴팁에 문구), 새로고침, 닫기. 빈 목록이면 "대화가 없어요".

#### FR-03 대화 화면 (M, v0.1)
- 스레드를 열면 캐시된 항목을 즉시 표시하고, `history` 기능이 있는 프로바이더(인스타)는 서버에서 최근 30개를 가져와 병합한다. 없는 프로바이더(카톡)는 "호스트가 켜진 뒤 받은 메시지만 보여요"를 한 줄 표시한다.
- 내 메시지 오른쪽, 상대 왼쪽. 항목 간 30분 이상 간격이면 날짜·시간 구분선. 그룹이면 상대 발신자 이름 표시.
- 새 메시지 도착 시 스크롤이 하단이었으면 자동 스크롤, 위로 올려 읽는 중이면 위치 유지.
- 뒤로 가기 버튼 또는 Esc로 목록 복귀.

#### FR-04 컴포저와 낙관적 전송 (M, v0.1)
- Enter 전송, Shift+Enter 줄바꿈. IME 조합 중(`isComposing` 또는 `keyCode 229`) Enter는 무시. 공백만이면 전송하지 않는다.
- `send` 기능이 없는 프로바이더(카톡 읽기 전용 판정 시)는 컴포저 대신 "이 메신저는 읽기 전용이에요"를 표시한다.
- 전송 즉시 "전송 중…" 말풍선(낙관적). 성공 시 확정 표시, 실패 시 "전송 실패" + 재시도 버튼과 원인 문구(예: "PC 카카오톡에서 이 방을 열어 두세요").
- 확정 규칙은 프로바이더별(FR-13, FR-17).
- **수용 기준:** Enter 후 50ms 이내 말풍선 표시, 한글 조합 중 Enter로 잘못 전송되지 않는다.

#### FR-05 상태 표시와 안내 (M, v0.1)
- 프로바이더별 상태를 색 점 + 한국어 문구로: `connecting` / `connected` / `degraded` / `disconnected` / `logged_out` / `rate_limited` / `error`.
- 조치가 필요한 상태(`disconnected`, `logged_out`, 호스트 미설치)는 프로바이더별 배너와 버튼([인스타그램 열기], [설치 안내]).
- 한 프로바이더의 장애가 다른 프로바이더의 표시·전송을 막지 않는다.

#### FR-06 툴바 아이콘 (S, v0.1)
- 클릭 시 활성 탭의 위젯 토글. 콘텐츠 스크립트가 없는 페이지(`chrome://`, 웹스토어, instagram.com)면 `panel.html?standalone=1`을 400×640 팝업 창으로 연다.
- 툴바 배지에 읽지 않은 합계.

#### FR-07 비텍스트 항목 표시 (M, v0.1)
- 인스타 `item_type`별 플레이스홀더: `media`→`[사진]`/`[동영상]`, `media_share`·`clip`→`[게시물 공유]`, `reel_share`·`story_share`→`[스토리 공유]`, `voice_media`→`[음성 메시지]`, `animated_media`→`[GIF]`, `like`→`❤️`, `link`→링크 텍스트, 그 외→`[item_type]`.
- 카톡은 알림에 보이는 텍스트만 받으므로 별도 분류 없음(사진 알림은 카톡이 주는 문구 그대로).

#### FR-08 프로바이더 설정 (S, v0.2)
- 프로바이더 켜기/끄기(`storage.local.providers`). 꺼진 프로바이더는 연결하지 않고 필터 칩에서도 숨긴다.

#### FR-09 편의 기능 (C, M7)
- 버블 드래그 이동·위치 기억, 다크모드, 새 메시지 OS 알림(`notifications` 권한 → ADR 후), 사이드패널 모드(`panel.html` 재사용).

### 인스타그램 프로바이더

#### FR-10 세션 재사용 (M, v0.1)
- 로그인 화면을 만들지 않는다. 엔진 탭에 `ds_user_id` 쿠키가 있으면 로그인 상태로 보고 즉시 inbox를 조회한다.
- 세션 만료(401/403, 로그인 페이지 리다이렉트, JSON 아닌 응답) 시 `logged_out` + 배너 [인스타그램 열기](엔진 탭을 앞으로).
- 로그인 완료 후 30초 이내(폴백 폴링 주기)에 별도 조작 없이 목록이 뜬다.
- **수용 기준:** 새 프로필에 설치 → 자동으로 열린 인스타 탭에서 로그인(2FA 포함) → 다른 사이트에서 버블 클릭 → 목록. 확장 안에 아무 입력도 없다.

#### FR-11 엔진 탭 관리 (M, v0.1)
- 시작 시와 패널이 열릴 때 `https://www.instagram.com/direct/*` 탭을 찾고, 없으면 `/direct/inbox/`를 **핀 고정·비활성** 탭으로 연다. 기존 instagram.com 탭이 있으면 그 탭을 쓴다(`/direct/` 우선).
- 탭 id는 `storage.session`에 저장해 서비스워커 재시작 후에도 재사용한다.
- 탭이 닫히면 `disconnected`, 패널이 하나라도 열려 있으면 1초 후 재생성. 없으면 다음 패널 열림 때.
- **수용 기준:** 패널을 연 채 엔진 탭을 닫으면 3초 안에 새 핀 탭이 생기고 `connected`로 돌아온다.

#### FR-12 실시간 수신 (M, v0.1)
- `hook.js`가 실시간 WebSocket 프레임을 감지하면 신호 → `ig-bridge.js`가 300ms 디바운스 후 inbox 재조회 → 목록 갱신·배지.
- 재조회 최소 간격 500ms, 동시 조회 1개. 폴백 폴링 15초. 429 시 30초 쿨다운, 연속되면 2배씩 최대 5분.
- **수용 기준:** 다른 기기에서 보낸 메시지가 패널에 p50 800ms 이내(NFR-01).

#### FR-13 텍스트 전송·확정 (M, v0.1)
- `client_context` 일치 또는 (같은 텍스트 + 15초 이내)이면 낙관적 항목을 서버 항목으로 교체한다. 전송 성공 후 500ms 뒤 inbox 재조회.
- **수용 기준:** 1.5초 이내 확정, 재조회 후 말풍선 중복 없음.

#### FR-14 읽음 처리 (S, v0.1)
- 안읽음 스레드를 열면 마지막 항목에 seen 요청, 로컬 unread 즉시 해제(실패해도 UI 유지).

### 카카오톡 프로바이더 (PoC 관문 통과 조건부, docs/04 §B)

#### FR-15 호스트 연결 (M, v0.2)
- `chrome.runtime.connectNative('com.buoy.kakao')`로 로컬 호스트에 연결하고 HELLO/HELLO_ACK 핸드셰이크로 기능(`capabilities`)을 받는다. 5초 안에 HELLO_ACK가 없으면 실패.
- 끊기면 1·2·4·8·16·30초 백오프로 재연결하고 `disconnected`(사유 포함)로 표시. 호스트 미설치면 [설치 안내].
- **수용 기준:** 호스트 프로세스를 강제 종료해도 30초 안에 자동 복구. PC 카톡을 껐다 켜면 `degraded`→`connected`.

#### FR-16 카카오 수신 (M, v0.2)
- 호스트 `ITEM` 이벤트를 방 스레드(`kakao:<방이름>`)로 병합. 같은 id는 한 번만. 열려 있는 방이 아니면 unread.
- 호스트가 켜진 뒤 관찰한 메시지만 보인다(`history=false`).
- **수용 기준:** 폰에서 보낸 메시지가 패널에 p50 1.5초 이내.

#### FR-17 카카오 전송·확정 (M — E2 실패 시 S로 강등하고 읽기 전용, v0.2)
- 호스트 `SEND` → `SEND_RESULT ok`면 낙관적 항목을 확정(로컬 id 유지), 실패면 실패 표시. `room_window_not_open`이면 "PC 카카오톡에서 이 방을 열어 두세요".
- **수용 기준:** 1.5초 이내 확정, 한글·이모지 정상, 5/5 성공.

#### FR-18 호스트 설치 도우미 (S, M6)
- `register.ps1` 또는 단일 exe로 등록. 확장은 `manifest.key`로 ID를 고정한다.

## 6. 비기능 요구사항

### NFR-01 성능

| 지표 | 목표 | 측정 |
|---|---|---|
| 인스타 수신: 엔진 탭 WS 프레임 감지 → 패널 반영 | p50 ≤ 800ms, p95 ≤ 1.5s | `[buoy][perf]` 로그, docs/04 §D |
| 카카오 수신: 호스트 ITEM 발생 → 패널 반영 | p50 ≤ 300ms (호스트 폴링 400ms 별도) / 폰 전송 → 패널 p50 ≤ 1.5s | docs/04 §D |
| 전송: Enter → 말풍선 | ≤ 50ms | 낙관적 UI |
| 전송: Enter → 확정 | p95 ≤ 1.5s (양쪽) | `SEND_RESULT` 시각 |
| 패널 열기 | 로드된 상태 ≤ 100ms, 최초 ≤ 500ms | `performance.now()` |
| 비교 기준 | 같은 메시지가 백그라운드 인스타 웹 탭 / 카톡 PC 토스트에 뜨는 시간보다 짧거나 같을 것 | docs/04 §D |
| 요청 빈도 | 인스타 inbox 조회 ≤ 2회/초, 10분 평균 ≤ 10회/분. 호스트 PING은 패널 열림 시 30초 1회 | 네트워크 탭, 호스트 로그 |

### NFR-02 신뢰성
- 서비스워커 재시작 시 상태 복구(`storage.session`), 패널 포트 끊김 800ms 후 재연결, 엔진 탭 재생성, 호스트 백오프 재연결.
- 확장 리로드 후 고아 콘텐츠 스크립트는 예외 없이 조용히 종료된다.
- 15초 응답 없는 요청(엔진·호스트)은 타임아웃으로 실패 처리한다.

### NFR-03 보안·프라이버시
- 확장·호스트 모두 외부 서버로 어떤 데이터도 보내지 않는다. 호스트는 네트워크를 쓰지 않는다.
- `sessionid` 등 HttpOnly 쿠키에 접근·저장하지 않는다. `ig-bridge.js`가 읽는 쿠키는 `csrftoken`, `ds_user_id`뿐. 호스트는 자격 증명을 다루지 않는다.
- 메시지 데이터는 `storage.session`에만(브라우저 종료 시 삭제). 호스트는 메시지를 저장하지 않는다.
- 호스트 페이지는 패널 내용에 접근할 수 없다(교차 출처 iframe, closed Shadow DOM). 창 간 메시지는 `__buoy` 플래그와 origin 검증.
- 로그(확장·호스트)에 메시지 본문·사용자 ID를 남기지 않는다.

### NFR-04 권한
- `permissions: ["storage", "nativeMessaging"]`, `host_permissions: ["https://www.instagram.com/*"]`, 콘텐츠 스크립트 `http://*/*`, `https://*/*`. `tabs` 권한은 쓰지 않는다.

### NFR-05 호환성
- Chrome 116 이상. Edge/Whale은 동작 확인만. 카카오 어댑터는 Windows 10/11.

### NFR-06 호스트 페이지 영향
- 패널을 열지 않은 탭에서 추가 메모리 ≤ 5MB, 레이아웃 변경 없음(fixed 요소만), 페이지 스크립트 오류 유발 없음.

### NFR-07 자원
- 상시 자원은 엔진 탭 1개, 서비스워커, 호스트 프로세스 1개(카카오 켜짐 시). 패널 iframe은 연 탭에서만.

### NFR-08 접근성
- 모든 버튼 `aria-label`, Tab 이동, 보이는 포커스 링, `prefers-reduced-motion` 시 애니메이션 제거, 명도 대비 4.5:1.

### NFR-09 유지보수성
- 인스타 응답 정규화는 `lib/normalize.js` 3함수에만. 인스타 엔드포인트·헤더 상수 1곳. 카톡과 닿는 상수 2곳(`CHAT_EDIT_CLASS`, `parse_kakao_toast`).
- 패널은 프로바이더 분기 대신 `capabilities`로 게이팅. 스레드·항목 id는 항상 `provider:id`.
- 프로토콜 정본은 `host/…/protocol.py` = docs/02 §8. 변경 시 `protocol` 번호를 올린다.

### NFR-10 언어
- UI 한국어. 한글 IME 조합 안전.

### NFR-11 호스트 무해성·견고성
- 호스트는 어떤 입력에도 죽지 않는다(잘못된 요청 → `ERROR`, 어댑터 실패 → `STATUS`/`SEND_RESULT`). stdout에는 프레임만 쓴다.
- 부품(전송·수신)이 없거나 실패해도 나머지는 동작하고 `degraded`로 무엇이 빠졌는지 알린다.
