# ADR-009. 저장소 뼈대는 선언된 구조 그대로 두고, 개발 편의는 의존성 0으로만 더한다

- 상태: 채택
- 날짜: 2026-09-07

## 맥락

제안서(문서 4개 + ADR 8개, PoC 코드)를 저장소로 옮긴 직후의 상태는 문서와 PoC뿐이었다. 확장 코드는 I-M0(인스타 엔드포인트 검증)이 끝나야 시작할 수 있고, 카카오 승격은 K-P1 관문 뒤다. 그 사이에 "프로젝트 기본 세팅"을 어디까지 할지 정해야 했다.

두 가지가 부딪혔다. 하나는 흔한 오픈소스 관례(LICENSE, CI, 린터, 포매터, 이슈·PR 템플릿)를 넣는 것이고, 다른 하나는 제안서가 이미 정한 규칙 — "신규 파일은 선언한 구조 밖에 만들지 않는다"(docs/03 §3), "번들 없이 바로 로드, 의존성 0"(docs/03 §2), "웹스토어 배포 없음, 개인 사용"(docs/01 §2) — 을 지키는 것이다.

## 결정

1. **디렉터리 뼈대만 만든다.** `lib/`, `host/`, `tests/`, `tests/fixtures/`, `icons/` 를 `.gitkeep`과 함께 만든다. 빈 스텁 파일(`background.js`, `widget.js`, `panel.js` 등)은 만들지 않는다.
2. **승격을 앞당기지 않는다.** `reference/` → 루트, `poc/extension-provider/lib/` → `lib/`, `poc/kakao-host/` → `host/` 이동은 각각 I-M1과 M5의 작업으로 남긴다(docs/03 §4).
3. **`package.json`은 스크립트 전용.** `private: true`, 의존성 없음. `test`(확장 순수 로직), `test:host`(호스트), `check`(문법·compileall·매니페스트 JSON), 그리고 셋을 묶은 `verify`.
4. **`.editorconfig`를 둔다.** LF·UTF-8·파일 끝 개행·후행 공백 제거, JS/JSON 2칸, Python·PowerShell 4칸, 마크다운은 후행 공백 유지.
5. **넣지 않는 것:** GitHub Actions(원격 저장소가 없어 실행될 곳이 없다), LICENSE(배포하지 않는 개인 사용), ESLint·Prettier·TypeScript·번들러(의존성 0 규칙, docs/03 §2는 TS를 I-M4 후 별도 ADR로 미뤄 두었다).

## 근거

- 빈 스텁은 "여기 뭘 넣기로 했더라"를 다시 뒤지게 만든다. 각 파일의 책임은 이미 docs/02 §3.1 표에 있고, 그게 정본이다.
- 완료 정의(CLAUDE.md)는 매 작업마다 `pytest`, `node --test`, `node --check`, `compileall`, 매니페스트 유효성을 요구한다. 손으로 네 번 치는 대신 `npm run verify` 한 번으로 묶으면 실제 반복이 줄고, 의존성은 하나도 늘지 않는다.
- 명령이 두 군데로 갈라지면 어긋나므로 CLAUDE.md "자주 쓰는 명령"에 `npm run verify`를 같이 적었다. 원본 명령 줄도 남겨 둔다.

## 결과

- 장점: 저장소 구조가 문서와 1:1로 유지된다. 검사 한 줄로 완료 정의를 만족시킬 수 있다.
- 단점 1: `verify`는 POSIX 셸 전용이다. `check`의 `for` 루프가 Windows cmd에서 돌지 않는다. **Windows에서 K-P1을 수행할 때는 CLAUDE.md의 개별 명령을 그대로 쓴다.**
- 단점 2: `check`는 `git ls-files '*.js'`를 쓰므로 **추적되지 않은 새 파일은 검사하지 않는다.** 새 파일은 `git add` 후에 검사된다. 제안서 원본 명령과 같은 동작이라 그대로 두었다.
- 단점 3: `package.json`의 스크립트는 지금 `poc/` 경로를 가리킨다. M5 승격 때 `test`와 `test:host` 두 줄을 `tests/`·`host/`로 바꿔야 한다.
- 원격 저장소를 만들면 CI 워크플로 추가를 재검토한다. `npm run verify` 한 줄이면 된다.

## 검토한 대안

- **일반 오픈소스 관례를 전부 추가:** LICENSE·CI·린터·템플릿. 배포하지 않는 개인 프로젝트라 대부분 돌지 않거나 읽히지 않고, 린터는 의존성 0 규칙과 충돌한다. 기각.
- **빈 스텁 파일까지 생성:** 구조가 눈에 보이는 장점보다, 아직 확정되지 않은 값(인스타 엔드포인트)을 추측해 채우고 싶은 유혹이 크다. 기각.
- **`package.json` 없이 문서의 명령만 유지:** 파일이 하나 줄지만 매 작업마다 네 명령을 손으로 친다. 완료 정의가 매번 요구하는 검사라서 스크립트가 값을 한다. 기각.
