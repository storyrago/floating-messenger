# ADR-008. 카카오 수신 경로는 Windows 알림 리스너를 1순위로 한다

- 상태: **제안** (E1 결과로 채택/변경. docs/04 §B3 결과 기록 후 갱신)
- 날짜: 2026-09-07

## 맥락
카카오톡 PC의 메시지를 프로그램이 읽는 방법은 (A) Windows 알림(토스트) 리스너 (B) 채팅창 UI Automation 텍스트 읽기 (C) 채팅창 내용 클립보드 복사 후 diff (D) 화면 OCR 이 있다. 클립보드 방식은 사용자의 클립보드를 계속 덮어써 상시 실행 위젯에 부적합하고, OCR은 느리고 부정확하다.

## 결정(제안)
- 1순위 **A**: 창을 열어 둘 필요가 없고 수백 ms 지연, 구현이 단순. 전제는 카톡 알림 켜짐 + 미리보기 켜짐 + Windows 알림 허용.
- 2순위 **B**: E1b에서 텍스트가 노출될 때만. 열린 방에 한해 1초 폴링·diff. A가 막히는 상황(카톡 창이 앞에 있어 알림이 안 뜰 때)의 보조.
- C, D는 채택하지 않는다.

## 근거
- 알림 리스너는 OS 공식 API(UserNotificationListener)라 카톡 내부 구조 변화에 상대적으로 강하다.
- 2026년 현재 Python(pywinrt)에서 폴링 방식 사용 예가 있다(ADR-006 F5).

## 결과
- 알림에 뜨지 않는 것(내가 보낸 메시지, 알림 끈 방, 방해 금지 중)은 못 읽는다. UI에 `history=false`와 안내로 드러낸다.
- 알림 텍스트 레이아웃(1:1/그룹)은 E1a로 확정하고 `parse_kakao_toast`에 반영한다.

## E1 결과에 따른 갱신 규칙
- E1a GO → 상태 "채택". 필요 시 B를 보조로 추가.
- E1a 실패·E1b GO → 결정을 B 단독으로 바꾸고 상태 "채택(변경)".
- 둘 다 실패 → 상태 "기각", 카카오 프로바이더 보류(docs/04 §B2).
