# ADR-006. 카카오톡은 로컬 네이티브 메시징 호스트가 PC 앱을 제어한다

- 상태: 채택 (PoC 관문 통과 조건부, docs/04 §B)
- 날짜: 2026-09-07

## 맥락

인스타에서 쓴 "브라우저 안의 웹 세션 빌리기"를 카카오에 적용할 수 있는지 2026-09에 조사했다.

확인된 사실

| # | 사실 | 근거 |
|---|---|---|
| F1 | 카카오톡은 공식 웹(브라우저) 클라이언트가 없다. 공식 데스크탑은 Windows/Mac 설치형 앱뿐 | kakaocorp.com 다운로드 페이지 |
| F2 | "카카오톡 웹버전"으로 검색되는 서비스는 제3자가 서버에서 PC 카톡을 띄워 화면을 스트리밍하는 방식. 계정·대화가 남의 서버를 거친다 | 나무위키 "카카오톡 웹버전" |
| F3 | 공식 카카오 메시지 API는 보내기 전용("나에게 보내기", 동의한 친구에게 보내기·쿼터·심사). 받은 메시지를 읽는 API는 없다 | developers.kakao.com 메시지 API, devtalk |
| F4 | 카카오톡 PC(Windows) 창을 win32 메시지로 제어해 전송·특정 방 새 메시지 감지·파일 첨부를 하는 도구가 2026년 4월에도 동작·배포 중 | 클리앙 자료실 2026-04-27 (autokakao) |
| F5 | Windows 10/11 `UserNotificationListener`로 다른 앱의 토스트(제목·본문)를 읽을 수 있고 Python(pywinrt)에서 폴링으로 쓰는 예가 있다. 사용자 권한 필요 | Microsoft Learn "Notification listener", PyPI wintoastlistener |
| F6 | 비공개 프로토콜(LOCO) 라이브러리는 유지보수가 끊겼거나 자주 깨지고 기기 등록·인증을 흉내내야 해 제재 위험이 크다 | node-kakao 등 아카이브 상태 |

## 결정
- 확장은 `chrome.runtime.connectNative('com.buoy.kakao')`로 로컬 호스트(Python)에 연결한다. `nativeMessaging` 권한을 추가한다.
- 호스트는 어댑터를 통해 카카오톡 PC 앱을 제어한다. Windows 어댑터: 수신은 알림 리스너 1순위(ADR-008), 전송은 채팅창 입력창 제어.
- 프로토콜은 `host/…/protocol.py`가 정본이며 docs/02 §8과 같다.
- 호스트는 네트워크를 쓰지 않고, 자격 증명을 다루지 않으며, stdout에는 프레임만 쓴다.
- PoC(docs/04 §B)의 E1·E2·E3·E4를 통과해야 통합(M5)을 시작한다. E1 전부 실패면 카카오 보류, E2만 실패면 읽기 전용으로 축소.

## 근거
- 인증 원칙(ADR-004) 유지: 사용자가 PC 카톡에 로그인돼 있으면 끝.
- F4로 실현 가능성이 확인됨. F5로 창을 열어 두지 않아도 되는 수신 경로가 있음.
- 호스트·프로토콜은 OS와 무관하고 어댑터만 갈아끼우면 되므로 macOS 확장 여지가 있다.
- mock 어댑터로 카톡 없이 전체 흐름을 자동 테스트할 수 있다(이미 통과).

## 결과
- 장점: 확장 쪽 구조(Provider 인터페이스)가 단순해진다. 카톡 대화는 PC 안에서만 움직인다.
- 단점: 설치 절차 증가(Python, 레지스트리). 카톡 PC 업데이트에 취약(상수 2곳·실험 스크립트로 완화). Windows 전용 시작. 과거 대화 불가·읽음 처리 불가·방 id가 이름(docs/01 §8). 카카오 약관 충돌 가능(개인 사용·테스트 계정·자동화 기능 없음).
